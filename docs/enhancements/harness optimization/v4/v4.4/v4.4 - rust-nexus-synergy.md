## 1. Problem Statement

The RTPI-Nexus platform deploys 10+ services behind Cloudflare Tunnel subdomains (provisioned by `rtpi-nexus/build.sh` Phase 1b). The nexus-console operator desktop connects to the C2's A2A gRPC plane and provides shell access to agents — but has no awareness of the broader service topology created by the deployment pipeline.

**Current gaps:**

1. **No service discovery.** The console's 5 fixed tabs (Dashboard, Transfer, Mesh, Kali, Chat) embed hardcoded localhost URLs via `option_env!()`. After `build.sh` provisions tunneled subdomains (`c3s-admin.onoiroi.us`, `c3s-empire.onoiroi.us`, etc.), the console has no way to discover or link to them. Most tunneled services have no tab at all.

2. **No build-to-deploy pipeline for all three binaries.** `nexus-server`, `nexus-agent` (Linux + Windows cross-compile), and `nexus-console` have never been built together in a single flow. The server has no production `nexus.toml`, and no agent has connected remotely via mTLS.

3. **No tunnel status visibility.** An operator running the console cannot see which tunnel services are active, access them with one click, or embed them as tabs — they must remember and type URLs manually.

**Target state:**
- Server and console deploy locally in one flow
- One Linux agent and one Windows agent connect remotely via mTLS
- Console auto-discovers tunnel services from `RTPI_SLUG` + `RTPI_DOMAIN` env vars
- **11 fixed tabs** — the existing 5 (Dashboard, Transfer, Mesh, Kali, Chat) plus 6 new ones (Workbench, Portainer, Wiki, VS Code, Reports, Kasm) — each with a tunnel badge linking to its subdomain
- Empire and Registry appear as status bar badges and can be opened as dynamic iframe tabs

### Phase 2: PKI + Server Deployment (Local)

#### 3.2a Generate full PKI suite

```bash
./target/release/nexus-server pki init \
  --domain c2.onoiroi.us \
  --ip $(hostname -I | awk '{print $1}') \
  --agents 2 \
  --out ./certs/prod
```

Output structure:
```
certs/prod/
├── ca.crt.pem              # PKI CA root — ALL parties trust this
├── ca.key.pem              # CA private key (secure offline after gen)
├── server.crt.pem          # Server cert (SAN: c2.onoiroi.us, local IP)
├── server.key.pem          # Server private key
├── operator.crt.pem        # Operator client cert
├── operator.key.pem        # Operator client key
├── console.crt.pem         # Console client cert
├── console.key.pem         # Console client key
├── agent-001.crt.pem       # Linux agent client cert
├── agent-001.key.pem
├── agent-002.crt.pem       # Windows agent client cert
└── agent-002.key.pem
```

#### 3.2b Server config

`nexus.toml` at repo root:
```toml

bind = "0.0.0.0:50052"
```

```bash

```

Services exposed: `:50052` (A2A gRPC), `:9100` (metrics + ferry gateway).

#### 3.4e Create ServiceTab component (shared by all 6 new fixed tabs + dynamic tabs)

**New file: `nexus-console/ui/src/components/service_tab.rs`**

A generic iframe embed component reused by all tunnel-backed tabs. Follows the same pattern as the existing `DashboardTab` and `KaliTab` but accepts URL and label as props instead of hardcoding them.

```rust
use leptos::prelude::*;

#[component]
pub fn ServiceTab(url: String, label: String) -> impl IntoView {
    let (loaded, set_loaded) = signal(false);
    view! {
        <div class="tab-content service-tab">
            {move || (!loaded.get()).then(|| view! {
                <div class="loading-overlay">
                    <p>{format!("Loading {label}...")}</p>
                </div>
            })}
            <iframe
                src=url
                class="embed-frame"
                allow="clipboard-read; clipboard-write; autoplay"
                on:load=move |_| set_loaded.set(true)
            />
        </div>
    }
}
```

Register in `components/mod.rs`:
```rust
pub mod service_tab;
```

#### 3.4f Refactor existing tabs + handle new variants in tab content area

## 11. Agent Health & Auto-Reconnect

The agent reconnection behavior is already implemented in `nexus-agent/src/main.rs:91-146` and `nexus-agent/src/a2a_client.rs`. This section documents the operational characteristics.

### 11.1 Connection Lifecycle

```
Agent start
    │
    ├── Initial jitter (10-40s random delay)
    │   Prevents thundering herd on mass deployment
    │
    ▼
┌──────────────────────────────────────────┐
│  connect_and_serve() loop               │
│                                          │
│  1. Dial C2 at NEXUS_SERVER_ADDR         │
│  2. Load mTLS config (priority order):   │
│     a. Embedded certs (compile-time)     │◄── ECHOTRIBBLE P3
│     b. Env vars (NEXUS_CA_CERT, etc.)    │◄── Standard path
│     c. System trust store (https://)     │◄── Fallback
│  3. Open A2A bidi stream                 │
│  4. Send agent-register first frame      │
│  5. Run inbound message loop             │
│     (shell-open, ferry tasks, etc.)      │
│                                          │
│  On clean stream close:                  │
│     log "C2 stream closed cleanly"       │
│     → immediate reconnect (no delay)     │
│                                          │
│  On error:                               │
│     log "C2 connect error: {e}"          │
│     → backoff: 60-360s random delay      │
│     → retry                              │
│                                          │
│  Loop runs forever (no max retries)      │
└──────────────────────────────────────────┘
```

### 11.2 OpMode Effects

| Behavior | `Lab` (default) | `Field` |
|----------|----------------|---------|
| Logging | `info` level, readable | Minimal, no file paths logged |
| Process name | `nexus-agent` | Polymorphic system-service name (`process_name.rs`) |
| Self-destruct | Disabled | Heartbeat/age/detection-triggered cleanup (`self_destruct.rs`) |
| Ephemeral state | Persistent KV | TTL-enforced KV with auto-expiry (`ephemeral_state.rs`) |
| Evasion checks | Skipped | Anti-debug + anti-VM checks (`evasion.rs`) |

### 11.3 mTLS Certificate Loading Priority

From `nexus-agent/src/a2a_client.rs:60-72`:

```
Priority 1: Embedded certs (compile-time, feature = "embedded-certs")
            → No disk I/O, no log of file paths
            → Built via `build-agent-bundles.sh --embed-certs`
            
Priority 2: Environment variable certs (runtime)
            → NEXUS_CA_CERT, NEXUS_CLIENT_CERT, NEXUS_CLIENT_KEY
            → Standard production path
            
Priority 3: System trust store (fallback)
            → Uses rustls default trust store
            → Only sufficient for server-auth TLS, not mTLS
```

### 11.4 Heartbeat

The A2A bidi stream acts as an implicit heartbeat — the gRPC HTTP/2 connection sends PING frames at the transport level. If the stream breaks, the agent detects it immediately and enters the reconnect loop.

In `Field` mode, the self-destruct module (`self_destruct.rs`) runs a separate heartbeat timer:
- If no successful C2 contact within the configured timeout (default: 24h), cleanup triggers
- If agent age exceeds max lifetime (configurable), cleanup triggers
- If evasion checks detect analysis environment, cleanup triggers

## 12. Windows Cross-Compile Details

### 12.1 Toolchain Setup

```bash
# MinGW toolchain (CI and development)
sudo apt-get install -y gcc-mingw-w64-x86-64
rustup target add x86_64-pc-windows-gnu

# Verify
x86_64-w64-mingw32-gcc --version
```

**MinGW vs MSVC distinction:**
- **MinGW** (`x86_64-pc-windows-gnu`): Used for cross-compiling the agent binary from Linux. Produces a standard PE executable. Suitable for CI.
- **MSVC** (`x86_64-pc-windows-msvc`): Required only for compiling the keylogger BOF (`bofs/keylogger/nexus_keylogger.c`) which needs `cl.exe`. Not available in cross-compile — `build.rs` creates an empty placeholder on non-Windows hosts.

### 12.2 Feature Flags Requiring Windows

These features compile to no-ops or stubs when cross-compiling from Linux:

| Feature | What It Enables | Cross-Compile Behavior |
|---------|----------------|----------------------|
| `bof-loading` | BOF loader + keylogger | Empty placeholder BOF; loader compiles but BOF is 0 bytes |
| `wmi-execution` | WMI query execution | Conditional `#[cfg(target_os = "windows")]` — excluded |
| `windows-specific` | Windows-only techniques | Conditional — excluded |
| `etw-observer` | ETW kernel context capture | Deferred — requires Windows build environment |
| `process-injection` | Process injection techniques | Conditional — Windows-only APIs |

### 12.3 Build Command

```bash

cargo build --release --target x86_64-pc-windows-gnu -p nexus-agent

# Output: target/x86_64-pc-windows-gnu/release/nexus-agent.exe

# With persistence kit (registry run keys — T1547)
```

### 12.5 Windows Service Lifecycle

From `nexus-agent/src/main.rs:53-77` and `nexus-agent/src/svc.rs`:

```
nexus-agent.exe --install     Create Windows service (SCM registration)
                              Service name: "NexusAgent"
                              Start type: Automatic
                              
nexus-agent.exe --uninstall   Remove Windows service
```

### 12.6 Known Limitations

1. **BOF keylogger**: Requires MSVC `cl.exe` for compilation. Cross-compile from Linux creates a 0-byte placeholder via `nexus-agent/build.rs`. The agent binary compiles and runs — BOF loading simply finds no payload.

2. **Fiber execution**: `nexus-agent/src/fiber_execution.rs` is Windows-only (`#[cfg(target_os = "windows")]`). It provides APC-based fiber execution for stealth. Not available in cross-compiled builds without a Windows CI runner.

3. **ETW observer**: `nexus-agent/src/sandbox/etw_observer.rs` — deferred; requires a Windows build environment with the Windows SDK.

The ferry protocol bridges nexus-harness (LLM orchestration) with rust-nexus (connectivity/delivery). This section documents the full data flow.

### 13.1 Protocol Definition

From `nexus-a2a/proto/a2a/v1/a2a.proto`:

```protobuf
// Lines 562-564 — Ferry RPCs
rpc SubmitHarnessTask(HarnessTask) returns (HarnessTaskResult);     // Unary
rpc StreamHarnessTask(stream HarnessTask) returns (stream HarnessTaskResult); // Bidi

// Line 282 — Task message
message HarnessTask {
```

### 13.2 Dispatch Architecture

```
nexus-harness                   rust-nexus C2                    nexus-agent
──────────────                  ─────────────                    ───────────
                                
 nexus-agent crate              nexus-a2a crate                  nexus-agent binary
 (harness side)                                                  
                                
 PgStore records    ─────►  SubmitHarnessTask RPC  ─────►    A2A bidi stream
 ferry task history          (a2a.proto:563)                  inbound dispatch
                                     │                              │
                                     ▼                              ▼
                             HarnessFerryHandler trait        BIDI_FERRY_HANDLER
                             (ferry_handler.rs)               (global static)
                                     │                              │
                                     │                    ┌─────────┴──────────┐
                                     │                    ▼                    ▼
                                     │             AgentFerryHandler    TechniqueBridge
                                     │             (harness_ferry.rs)   (harness_bridge.rs)
                                     │                    │                    │
                                     │                    │  Rate-limiting     │  ATT&CK
                                     │                    │  (max_concurrent)  │  technique

                                     │                    ▼                    ▼

                                     │             (execution.rs)       ::execute()
                                     │             27KB, main exec      (techniques/mod.rs)
                                     │                    │                    │
                                     │                    └────────┬───────────┘
                                     │                             ▼
                                     │                      HarnessTaskResult
                                     │                      (output, is_error,
                              ◄──────┘                       duration, kernel_context)
```

### 13.3 Handler Selection

The agent initializes the ferry handler during startup. Two handler implementations exist:

| Handler | File | Use Case |
|---------|------|----------|
| `AgentFerryHandler` | `nexus-agent/src/harness_ferry.rs` | General-purpose: maps `tool_name` to `TaskExecutor` methods (shell, file ops, system commands) |
| `TechniqueBridge` | `nexus-agent/src/harness_bridge.rs` | ATT&CK-specific: maps `tool_name` to registered `AttackTechnique` implementations by technique ID or task type |

The handler is set globally via `set_bidi_ferry_handler()` in `a2a_client.rs:27-29`, using a `OnceLock<Arc<dyn HarnessFerryHandler>>`.

### 13.4 Rate Limiting & Telemetry

`AgentFerryHandler` includes built-in rate limiting and GML telemetry:

- **Rate limiting**: `max_concurrent` field (0 = unlimited). Active tasks tracked via `AtomicU64`. Exceeding the limit returns an error result (not a gRPC status error — the harness sees a `HarnessTaskResult` with `is_error: true`).

- **Telemetry**: Every task dispatch records metrics via `TelemetryAggregator`:
  - `record_task()` — increments task count
  - `record_message()` — tracks bytes sent/received per direction
  - `record_error()` — tracks error rate
  - Window-based flush: every `TELEMETRY_WINDOW` (1 hour), the aggregator flushes a `TelemetrySnapshot` and submits it to the GML adjustment layer via `SubmitTelemetrySnapshot` RPC.

## 15. TLS Certificate Chain

Two independent TLS planes operate in the v4.4 deployment. They share no certificate material.

### 15.1 Plane 1: Web Services (Browser → Tunneled Services)

```
┌──────────┐      TLS 1.3       ┌───────────────┐     Encrypted     ┌─────────────┐
│  Browser │ ──────────────────► │  Cloudflare   │ ─────────────────► │  cloudflared│
│          │   Universal SSL     │  Edge         │   Tunnel protocol  │  daemon     │
│          │   (auto-renewed)    │  (CDN + WAF + │                    │  (origin)   │
└──────────┘                     │   Zero Trust) │                    └──────┬──────┘
                                 └───────────────┘                          │
                                                                  ┌─────────┴─────────┐
                                                                  │  Origin services   │
                                                                  │  (HTTP/HTTPS)      │
                                                                  │                    │
                                                                  │  :8443 kasm-proxy  │
                                                                  │  :5000 RTPI        │
                                                                  │  :7777 SysReptor   │
                                                                  │  :1337 Empire      │
                                                                  │  :9443 Portainer   │
                                                                  │  etc.              │
                                                                  └────────────────────┘
```

| Segment | Certificate | Issuer | Validity |
|---------|-------------|--------|----------|
| Browser → Cloudflare | Universal SSL | Cloudflare / Google Trust | Auto-renewed |
| Cloudflare → Origin | Cloudflare Tunnel (encrypted) | Cloudflare Tunnel auth | Tunnel credential lifetime |
| Origin internal | Self-signed (kasm-proxy) or plaintext HTTP | kasm-proxy-init / none | Auto-generated |

**Key point:** No exposed ports. All web traffic enters through the tunnel. The origin server's firewall blocks all inbound HTTP/HTTPS except from the `cloudflared` daemon.

### 15.2 Plane 2: C2 mTLS (Agent ↔ Server)

```
┌──────────────┐      mTLS (HTTP/2)       ┌──────────────┐
│  nexus-agent │ ────────────────────────► │ nexus-server │
│              │                           │              │
│  Presents:   │                           │  Presents:   │
│  agent-001   │                           │  server.crt  │
│  .crt.pem    │     Both verify:          │  .pem        │
│              │     ca.crt.pem            │              │
│  Verifies:   │     (shared PKI root)     │  Verifies:   │
│  server.crt  │                           │  agent-001   │
│  via CA      │                           │  .crt via CA │
└──────────────┘                           └──────────────┘
```

| Segment | Certificate | Issuer | Key Type | SAN |
|---------|-------------|--------|----------|-----|
| CA root | `ca.crt.pem` | Self-signed (rcgen) | Ed25519 | — |
| Server | `server.crt.pem` | `ca.crt.pem` | Ed25519 | `c2.onoiroi.us`, local IP |
| Operator | `operator.crt.pem` | `ca.crt.pem` | Ed25519 | CN=operator |
| Console | `console.crt.pem` | `ca.crt.pem` | Ed25519 | CN=console |
| Agent N | `agent-{N}.crt.pem` | `ca.crt.pem` | Ed25519 | CN=agent-{N} |

**PKI generation:** `nexus-server pki init` (implemented in `nexus-infra/src/pki.rs`, `PkiManager::init()`). Supports both self-signed CA mode and Cloudflare-issued CA mode (`--cf-token`).

**Port exposure:** Port 50052 is the ONLY port exposed to the network for C2 traffic. It is protected by mTLS — connections without a valid client cert signed by the CA are rejected at the TLS handshake.

### 15.3 Certificate Rotation

| Step | Command | Downtime |
|------|---------|----------|
| 1. Mint new agent cert | `nexus-server pki agent --certs-dir ./certs/prod --name agent-003` | None |
| 2. Transfer to agent host | `scp agent-003.{crt,key}.pem user@host:` | None |
| 3. Restart agent with new cert | Set `NEXUS_CLIENT_CERT`/`NEXUS_CLIENT_KEY` → restart | Agent reconnects (~10-40s) |
| 4. Full CA rotation | Re-run `pki init` with new output dir → distribute all certs | Full stack restart |

## 19. Risk Register

| ID | Risk | Likelihood | Impact | Mitigation |
|----|------|-----------|--------|------------|
| R1 | Tauri build fails due to webkit2gtk version mismatch on non-Ubuntu distros | Medium | High | Pin system deps in deploy script; test on clean Ubuntu 22.04/24.04; document exact apt package versions |
| R2 | Windows cross-compile fails with MinGW linking errors (missing symbols, ABI mismatch) | Medium | Medium | CI matrix with `x86_64-pc-windows-gnu` target; fallback to MSVC build on a Windows GitHub Actions runner |
| R3 | mTLS certificate expiry goes undetected, agents lose connectivity | Low | Critical | Log certificate remaining validity on agent startup; add cert expiry metric to Prometheus; alert at 30-day threshold |
| R4 | Tunnel service iframes blocked by Content-Security-Policy or X-Frame-Options headers | Medium | Medium | Cloudflare Access may add `frame-ancestors` restrictions; test each service embed individually; configure per-service CSP overrides in tunnel ingress config; fallback to "Open in browser" link |
| R5 | Agent reconnect storm after server restart overwhelms the server | Low | Medium | Already mitigated: agents use 60-360s random backoff on error (`main.rs:142`); server rate-limiter at 100 RPS (`nexus.toml [rate_limit]`) |
| R6 | Console tab bar overflow — 11 fixed tabs + dynamic shell/audit tabs exceed horizontal space | Medium | Low | Implement horizontal scroll on the tab bar, or collapse to icon-only mode below 1024px width; test at 1280px minimum |
| R7 | `tauri-plugin-tray-icon` crate missing from index (B1 blocker from v4 plan) | Known | High | Pin to existing crates.io version; vendor locally if needed; or remove tray icon feature and use a simpler system tray approach |
| R8 | PKI `pki init` generates certs with incorrect SAN — agents fail hostname verification | Low | Critical | Integration test: generate certs → connect agent → verify handshake succeeds; existing test in `nexus-infra/src/pki.rs:585` covers self-signed mode |

## 21. Monitoring & Observability

### 21.1 Server Metrics

The nexus-server exposes a Prometheus-compatible metrics endpoint on port 9100 (implemented in `nexus-infra/src/metrics_server.rs`).

```yaml
# Add to Prometheus scrape config (prometheus.yml)
scrape_configs:
  - job_name: 'nexus-server'
    static_configs:
      - targets: ['192.168.1.81:9100']
    scrape_interval: 15s
```

**Available metrics:**
- `nexus_a2a_connected_agents` — Current connected agent count
- `nexus_a2a_messages_total` — Total gRPC messages (by direction)
- `nexus_ferry_tasks_total` — Ferry task submissions (by status: success/error)
- `nexus_ferry_task_duration_seconds` — Task execution duration histogram
- `nexus_audit_entries_total` — Audit log entries written

### 21.2 Agent Telemetry

Each agent runs a `TelemetryAggregator` (from `nexus-mesh/src/telemetry.rs`) that collects per-window metrics and submits them to the GML adjustment layer via `SubmitTelemetrySnapshot` RPC.

**Per-window counters** (default window: 1 hour):
- `message_count` — Messages processed
- `bytes_sent` / `bytes_recv` — Data transfer volume
- `task_count` — Ferry tasks executed
- `error_rate` — Error ratio
- Kernel context: `total_syscalls`, `total_memory_allocated`, `total_processes_spawned`, `total_files_touched`, `total_network_connections`, `sandbox_violations`

### 21.3 Console Health

The nexus-console provides visual health indicators:

| Indicator | Location | States |
|-----------|----------|--------|
| Connection status | Status bar (left) | Connected (green) / Disconnected (red) / Connecting (yellow) |
| Mesh status | Status bar (center) | Dual-connected / gRPC-only / Disconnected |
| Agent count | Status bar (right) | Number of registered agents |
| Tunnel badges | Tab bar (per tab) | Active (green dot) / Unavailable (grey dot) |
| Tray icon | System tray | Connected / Disconnected / Error |

## 22. Rollback Plan

### Per-Phase Rollback

| Phase | Rollback Procedure | Data Loss Risk |
|-------|-------------------|----------------|
| **Phase 1 (Build)** | No rollback needed — binaries are local build artifacts. Delete `target/release/` to clean up. | None |
| **Phase 2 (PKI + Server)** | Stop nexus-server process. Delete `certs/prod/` directory and `server-identity.bin`. Revert `nexus.toml` changes. | None (certs are regenerable) |
| **Phase 3 (Remote Agents)** | SSH to each remote host: kill agent process, delete agent binary + cert files. On Windows: `nexus-agent.exe --uninstall` to remove the service. | None |
| **Phase 4 (Console)** | Rebuild console without tunnel env vars (`RTPI_SLUG`/`RTPI_DOMAIN` unset). Console reverts to 5-tab mode with localhost URLs. No code changes needed — the 6 new tabs simply don't appear when tunnel config is absent. | None |

### Full Rollback

To completely revert v4.4:

```bash
# 1. Stop all components
kill $(pgrep nexus-server)
ssh linux-target-01 'kill $(pgrep nexus-agent)'
# Windows: sc stop NexusAgent && sc delete NexusAgent

# 2. Remove cert material
rm -rf certs/prod/

# 3. Remove server config
rm nexus.toml

# 4. Rebuild console (reverts to 5 fixed tabs)
cd nexus-console/src-tauri && cargo tauri build
# Console code is additive — the TunnelConfig/ServiceTab code
# is inert without RTPI_SLUG/RTPI_DOMAIN env vars.

# 5. Clean up remote hosts
ssh linux-target-01 'rm -f /opt/nexus-agent /opt/nexus-certs/*'
```

### Partial Rollback: Console Only

If only the console tunnel badge connector needs reverting:

```bash
# Simply launch without tunnel env vars — existing code handles the fallback:
# - No RTPI_SLUG/RTPI_DOMAIN → TunnelConfig is None
# - 6 new fixed tabs render with localhost fallback URLs
# - Badge dots don't appear
# - Status bar services section is empty

./target/release/nexus-console
# Result: original 5-tab experience (Dashboard, Transfer, Mesh, Kali, Chat)
# plus the 6 new tabs pointing at localhost defaults
```
